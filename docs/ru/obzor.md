# Обзор WSC (Web Security Connect)

**WSC** — корпоративная платформа безопасного доступа к внутренним WEB-приложениям через единый портал. Пользователь работает с целевыми системами (Wazuh, CRM, панели администрирования и др.) **внутри WSC**, без раскрытия реальных URL. Весь трафик к приложениям проходит через шлюз с **Browser Isolation** и **WAF (ModSecurity + OWASP CRS)**.

## Зачем это нужно

Организации дают сотрудникам доступ к чувствительным веб-системам, но не хотят:

- публиковать внутренние URL наружу;
- ставить клиентские агенты или расширения для записи;
- открывать приложения в отдельных вкладках браузера без контроля.

WSC решает это единым порталом: каталог приложений, удалённый браузер на сервере, проверка запросов WAF и централизованная аналитика сеансов.

## Три прикладных сервиса + WAF

| Компонент | Роль простыми словами |
|-----------|------------------------|
| **wsc-gateway** | Портал с боковым меню, каталог приложений, Browser Isolation, стрим интерфейса, маскирование URL, idle сессии приложения |
| **wsc-management** | Админка: пользователи, RBAC, приложения, TLS-сертификаты, правила WAF, интеграции (AD/LDAP, SMTP, OIDC/SAML) |
| **wsc-analytics** | Сеансы, скриншоты, события WAF, отчёты и экспорт |
| **wsc-waf** | Sidecar OpenResty/Nginx + ModSecurity 3 + OWASP CRS; доступен **только** из gateway, не снаружи |

Инфраструктура: PostgreSQL, Redis, MinIO (объектное хранилище скриншотов и артефактов).

## Как работает доступ для пользователя

1. Единый вход (логин) → после авторизации **переключатель контуров** по правам: Portal / Management / Analytics.
2. В портале — **sidebar** (Приложения, Активные сессии, Профиль и пункты по RBAC) и область контента.
3. Выбор приложения открывает **in-app workspace** внутри портала (не новое окно браузера). Есть кнопка «Назад к каталогу».
4. Пользователь видит только URL шлюза (`/workspace/<opaqueId>/...` или `/a/<slugHash>/...`). Реальный hostname целевого приложения скрыт (**URL masking**).
5. Интерфейс целевого приложения стримится с удалённого Chromium на gateway (**Browser Isolation**, вариант A).

## Browser Isolation

На gateway запускается Chromium (Playwright). Пользователь получает поток UI (WebRTC/WebSocket). HTTP(S) из isolation идёт только через WAF к allowlisted upstream. Cookie jar изолирован между приложениями. Скриншоты пишутся на сервере по политике приложения — без заметного клиентского агента.

## WAF (ModSecurity + OWASP CRS)

Весь трафик isolation → upstream обязан пройти через **wsc-waf**. Режимы на приложение: `Off` | `DetectionOnly` | `Prevent`. В scope — SQL-инъекции, XSS (reflected/stored на request; опционально inspection response) и классы атак CRS. Блок показывает брендированную safe-page **внутри workspace**. События WAF попадают в analytics и могут сопровождаться скриншотом.

## Idle: приложение vs портал

- **App-idle** — бездействие в viewer отключает только сессию к целевому приложению; портал и SSO остаются. Toast: «Сессия приложения завершена по бездействию».
- **Portal-idle** — отдельная, более длинная политика logout с портала.

## TLS и интеграции

- Сертификаты **per-app**: CA, client cert/key, mTLS, SNI, мониторинг срока действия.
- Интеграции: AD/LDAP, OIDC/SAML, SMTP, syslog/webhooks, Management API; SCIM — фаза 2.

## Роли

| Роль | Контур |
|------|--------|
| End User | Portal |
| App Owner / Security Admin / System Admin | Management |
| Analyst / Auditor | Analytics |

Дизайн единый во всех контурах (`@wsc/ui`).
